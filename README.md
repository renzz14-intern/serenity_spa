# Serenity Spa — Spa Booking Website

**Developer:** Lawrence Fortin  
**Program:** BSIT — Technical Services Management  
**Status:** Academic web application, run locally with XAMPP; not deployed online.

## Overview

Serenity Spa is a PHP/MySQL web application for browsing spa services and making appointment bookings. The project includes registration and login, service selection, a health-information step, booking details, appointment-related pages, and administrative booking-management code. HTML, CSS, and JavaScript support the front-end experience; PHP handles server-side logic; MySQL stores application data.

## Local setup (XAMPP)

1. Install XAMPP with Apache, MySQL/MariaDB, and PHP's `mysqli` extension.
2. Copy this project folder into XAMPP's `htdocs` directory.
3. Start Apache and MySQL from the XAMPP Control Panel.
4. Copy `local_config.example.php` to `local_config.php` in the project root. Change the database username/password/name to match your local setup. Keep `local_config.php` private; it is excluded by `.gitignore`.
5. Open phpMyAdmin, create/import the database using `database/schema.sql`. The included schema creates/selects `users_db` by default; change both the SQL and local configuration consistently if you use a different name.
6. Install Composer if it is not installed, then run `composer install` from the project directory to install PHPMailer.
7. Open the website through Apache, for example `http://localhost/serenity_spa/`. Use the appropriate page for the workflow you want to test.
8. Test registration, login, service loading, booking submission, appointment history, and admin access using fictional test data before presenting the project.

### Email setup

Email features require your own SMTP settings in `local_config.php` under the `mail` key. Do not paste an SMTP password into tracked PHP files or upload it to GitHub. If email is not configured, do not claim email delivery has been tested.

### Administrator account

The registration flow assigns the ordinary `user` role by default. The project does not include a safe public default administrator account. Only a trusted local database administrator should grant the `admin` role to an authorized test account. Never give administrator privileges to arbitrary public registrations.

## Database

`database/schema.sql` documents the table structure extracted from the supplied database dump after removing data records. It includes tables for users, bookings, appointments, services, therapists, and health alerts. Review and test the schema in a new local database before use. Confirm the relationships and expected fields against the SQL queries in the current application; the original archive contained multiple differing SQL scripts, so the schema should not be treated as production-verified.

## Security notes and limitations

- This is an academic project and is **not production-ready**.
- The original archive contained embedded SMTP credentials. They have been removed from this cleaned copy and replaced with local configuration. If the original SMTP password is active, revoke/rotate it.
- The administrative booking page's authentication bypass was replaced in this copy with a role check. Retest admin workflows after making this change.
- Further security review is required, including CSRF protection, session hardening, authorization on all administrative routes, output/input validation, error handling, and protection of health-related and personal data.
- The original SQL dump contained personal account and booking records; it is not included in this repository copy.
- Debug logs, debug/setup scripts, duplicate SQL scripts, and installed vendor dependencies are excluded.
- The application has not been deployed online. No live demo or public GitHub repository is currently available.
- Some files in the supplied source are empty/incomplete, and some links may point to missing pages. Confirm them before claiming those features are finished.
